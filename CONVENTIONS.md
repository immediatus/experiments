# Conventions

The standard every experiment in this repository follows. It exists so that any number in a
blog series can be traced to the code that produced it, regenerated by anyone, and checked
without trusting the author. It follows
[Ten Simple Rules for Reproducible Computational Research](https://doi.org/10.1371/journal.pcbi.1003285)
(Sandve et al., 2013) and
[Good Enough Practices in Scientific Computing](https://doi.org/10.1371/journal.pcbi.1005510)
(Wilson et al., 2017), and aims at the ACM artifact levels *Available*, *Functional* and
*Reusable*.

## 1. One experiment per blog series

An experiment is a folder at the repository root, named by the **series' URL slug**: the
part of the post URLs before `-part1` (`capacity-in-arrears` for
`/blog/capacity-in-arrears-part1-one-bit-per-dead-time/`). Experiments never import from each
other. Shared utilities live in [`tools/`](tools/) and are covered by their own tests.

## 2. Layout of an experiment

```
<series-slug>/
  README.md          what the experiment is, the series and its posts, the checks, what is where
  experiment.json    the manifest (below)
  reproduce.py       the single entry point: the sections, with the command line of tools/harness.py
  NOTICE             optional: third-party sources the code derives from
  model/             the simulations and any port of third-party logic
  tests/             every test of the experiment, its kit's included, run by reproduce.py --check
  expected/          results.txt: the frozen output the posts quote
  figures/           optional: figspec.py and the SVG figures it draws from expected/results.txt
  docs/              one page per part, CLAIMS.md, SECTIONS.md, FALSIFICATION.md,
                     ASSUMPTIONS.md, SOURCES.md
  <kit>/             optional: a kit for testing predictions on real infrastructure
                     (cluster/ in capacity-in-arrears)
```

An experiment's top level holds only the four files named above; everything else lives in a
folder.

The manifest, `experiment.json`, describes the experiment to the repository's tools:

```json
{
  "title": "the series' title",
  "slug": "the folder's name",
  "blog": "https://the-blog",
  "posts": [{"part": 1, "title": "the post's title", "url": "https://the-blog/..."}],
  "python": ">=3.10",
  "dependencies": [],
  "specimen": {"free-form": "the versions and settings the experiment simulates"}
}
```

Every field but `specimen` is required; parts are numbered 1, 2, ... in order, every post lies
under `blog`, and `dependencies` stays empty. [`tools/check_repo.py`](tools/check_repo.py)
enforces this section: the layout, the manifest, and the repository's README and CHANGELOG
listing the experiment.

## 3. Code

- Python 3.10 or later, **standard library only**, so a reader installs nothing. Development
  tools are pinned in `requirements-dev.txt`; `pyproject.toml` holds their configuration.
- Every random draw has a fixed seed in the code.
- `reproduce.py` has one section per table or figure of the series: a function `t1`, `t2`,
  ... that prints a header line starting with its name (`T1 `, `T2 `, ...) and then its rows.
  It ends by handing its command line to [`tools/harness.py`](tools/harness.py), which finds
  the sections and provides the rest: `python3 reproduce.py T4` prints one section; `--check`
  runs `tests/`, then every section, and compares the output with `expected/results.txt` byte
  for byte; `--figures` redraws the figures and `--figures --check` compares them.
  [`tools/results.py`](tools/results.py) reads the results back, for figures and checks.
- Entry points find `model/`, `figures/` and `tools/` from their own location, so every
  command works from any directory.
- Files in `model/` are libraries: no `__main__` block, defaults equal to the series' specimen,
  and a docstring for every public function that names its inputs, outputs and units. Each
  closed-form result of the posts is one function, used by every section that compares with it.
- A section derives every scale it reports in (pods needed, seconds of demand) from the run
  it reports on, never from a constant that assumes the default inputs.
- `tests/` checks the model as well as any port: properties the model must have whatever its
  inputs, such as conservation of work, and each closed form against the simulation.
- Files are read and written as UTF-8 explicitly.
- Floating-point sums use `math.fsum`, which is exactly rounded on every Python version; the
  built-in `sum` of floats changed in Python 3.12 and would make results depend on the version.

## 4. Figures

A figure exists once, as a specification built from `expected/results.txt` by
`figures/figspec.py`. [`tools/svg.py`](tools/svg.py) draws it for the repository, and the
blog draws the same specification for the post, so the two cannot disagree. Every figure has
a title, a description for screen readers, light and dark palettes, and direct labels for
every number the text quotes. A numeric table of four or more rows is drawn as a figure.

## 5. Documents

- `README.md` explains the experiment to someone arriving from the blog and links to every post.
- One page per part restates the post's belief, mechanism, law, results, bill and what a
  reader can vary, with the series' layer tag on each result: **Bound** (proof or source),
  **Fit** (reading or approximation), **Estimate** (simulation). Pages never add claims the
  posts do not make.
- `docs/CLAIMS.md` maps every claim to its section, figure and post paragraph.
- `docs/SECTIONS.md` has a table row for every section, `| T1 | what it prints |`, and no
  other.
- `docs/FALSIFICATION.md` lists the predictions that would refute the series, with a status
  that changes only with a reported run, and ends with a "Reporting a run" section: what a
  report must attach for this experiment's kit. The repository's issue templates stay generic
  and point to that section, so they serve every experiment.
- The repository links to the blog. **The blog never links to the repository.**
- [`tools/check_docs.py`](tools/check_docs.py) must pass: every link resolves, every post link
  is listed in `experiment.json`, every section exists, every claimed number is in the
  results.

## 6. Checks before an experiment's first release

```bash
python3 tools/check_all.py --full   # every check of every experiment, as CI runs it
```

It runs the shared tools' tests, `tools/check_repo.py`, the Python 3.10 floor and a compile of
every file, then, for each experiment, `tests/`, `tools/check_docs.py`,
`reproduce.py --figures --check` and `reproduce.py --check`. Lint runs separately with the pinned tools
in `requirements-dev.txt`.

Continuous integration runs `python3 tools/check_all.py` on every push to main and every pull
request, on Python 3.10 to 3.14, and `--full` weekly, on release tags and on demand, on Python
3.10 and 3.14. Before the first release, a scan for local paths, private names and credentials
comes back empty, and every file has been read once.

## 7. Releases and errata

- A release is tagged `<slug>-v<major>.<minor>` and archived with a DOI (Zenodo). The tag that
  matches the published series is the reference for its numbers.
- A published experiment changes only by a dated erratum: an entry in `CHANGELOG.md` saying
  what changed, why, and which numbers moved. If a number in a post moves, the post is
  corrected too.
- A falsification criterion that a reported run refutes is recorded as `REFUTED` with a link
  to the report, and the claim is rewritten in the post, not softened.
